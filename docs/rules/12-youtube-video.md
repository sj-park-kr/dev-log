## 12. 영상 제작과 유튜브 업로드
새 글 한 편마다 1분 안팎의 설명 쇼츠와 세로 썸네일을 함께 준비한다. 영상은 글과 같은 비유·같은 아이콘으로 글의 페이지 제목들을 차례로 짧게 훑는 요약이다. 글의 그림을 그대로 장면으로 써도 된다. 글 작성 요청에 이 과정도 포함한다. 수동 작성과 [하루 한 편 자동 글쓰기](../daily-writing-prompt.md) 모두 같은 순서를 따른다. 사용자가 검토를 마치면 해당 단계부터 별도 제작 요청 없이 이어간다.

### 순서
1. 글을 쓰고 [검토 규칙](08-review.md)을 마친 뒤 **사용자에게 글 검토를 받는다.**
2. 사용자가 글을 승인하면 영상 나레이션 대본을 먼저 사용자에게 전달한다.
3. Gemini TTS로 대본의 WAV 음성 파일을 생성해 영상을 만든다. 영상 제작은 아래 [모델](#모델) 규칙을 따른다.
4. 영상과 9:16 썸네일을 사용자에게 보여 주고 **공개 전 검토를 받는다.** 썸네일은 같은 시리즈의 앞 편을 참고하고, 휴대폰 크기에서 제목과 핵심 그림이 읽히는지 확인한다.
5. 승인되면 글 경로와 함께 업로드 스크립트를 실행한다. 공개 재생을 확인한 뒤 썸네일을 올리고 쇼츠 링크의 미리보기에 새 썸네일이 반영됐는지 확인한다.
6. 스크립트가 글 front matter의 `youtube:`에 영상 ID를 넣는다. 그러면 글 맨 위, 한 줄 요약 앞에 영상이 뜬다. 최종 보고에 `https://www.youtube.com/shorts/<ID>` 링크를 쓴다.

### 나레이션 음성
- Gemini TTS의 `gemini-3.8-flash-lite-tts` 모델과 `Kore` 목소리로 한국어 나레이션을 생성한다.
- API 키는 프로젝트 루트의 `.env`에 있는 `GEMIN_API_KEY`를 스크립트에서 읽는다. 키를 출력하거나 저장소에 추가하지 않는다.
- Gemini TTS의 비스트리밍 기본 응답은 완성된 WAV다. 응답 형식과 `RIFF`·`WAVE` 헤더를 확인하고, 완성된 WAV는 받은 바이트를 그대로 저장한다. WAV 헤더는 헤더 없는 PCM임을 확인했을 때만 붙인다. WAV를 PCM처럼 감싸면 끝부분의 메타데이터가 소리로 재생되어 문장 사이에 지직거리는 소리가 난다. 편집과 합치기는 ffmpeg 같은 WAV 디코더로 읽은 음성 샘플로 한다. [Gemini 음성 출력 형식](https://ai.google.dev/gemini-api/docs/speech-generation#audio-output-formats)
- 생성한 음성을 들어 발음과 대본 누락을 확인하고, 필요한 부분은 다시 생성한다. 무료 사용량과 과금 여부는 사용 중인 계정에서 확인한다.
- 합친 WAV와 최종 MP4에서 각 문장 앞뒤와 마지막 음성 뒤의 쉼을 확인한다. 쉼에 지직거리는 소리나 클릭이 있으면 원본 클립과 비교하고 WAV를 올바르게 읽었는지 확인한다. 수정한 뒤에는 같은 구간을 다시 재생해 말끝이 잘리지 않았는지까지 확인한다.

### 모델
- 영상을 만드는 서브에이전트는 **Opus**(`model: "opus"`)에 effort를 **`xhigh`**로 지정해 띄운다. 최소 `high`이고, 기본은 `xhigh`다. 지정하지 않으면 낮은 설정으로 돌아가므로 반드시 적는다.
- Opus가 아닌 모델이나 `high` 미만 effort로 영상을 만들지 않는다.

### 폴더와 파일
영상 작업물은 `_motion/<슬러그>/`에 둔다. `_motion/`은 `.gitignore` 대상이라 저장소에 올라가지 않는다.

| 파일 | 내용 |
|---|---|
| `<슬러그>.mp4` | 올릴 영상. 폴더에 mp4는 하나만 둔다(스크립트가 첫 mp4를 쓴다) |
| `youtube.md` | 업로드 문안. 아래 형식을 지킨다 |
| `thumbnail.png` | 쇼츠 미리보기에 쓸 9:16 썸네일 |
| `render.mjs`, `index.html`, wav | 영상 제작 원본 |

`youtube.md` 형식(스크립트가 이 형식을 읽는다):
- 제목 후보를 `1. **제목**` 형태의 번호 목록으로 쓴다. **1번이 올라간다.** 100자를 넘기지 않는다.
- 설명란은 ` ``` ` 코드블록 **하나**로 쓴다. 이 블록이 설명으로 올라간다.
- 설명란의 글 링크는 메인이 아니라 그 글의 정확한 주소로 쓴다(`https://sj-park-kr.github.io/dev-log/YYYY/MM/DD/<파일명 슬러그>/`).
- 클로바더빙 음성을 사용하면 [네이버 출처 표기 안내](https://help.naver.com/service/23823/contents/12465?lang=ko&osType=COMMONOS)에 따라 설명란에 서비스명, 사용한 AI 보이스명 해시태그와 서비스 링크를 적고, 영상 제목·워터마크·시작 자막 중 하나에도 안내에 맞게 표기한다. 보이스명을 모르면 사용자에게 확인한다. 적용되는 이용 조건도 확인한다.

### 쇼츠 규격
영상은 **유튜브 쇼츠로 올라가도록 세로로 만든다.** 가로 영상(16:9)으로 만들지 않는다.
- 해상도는 **1080×1920(9:16)**, 30fps, H.264(`yuv420p`) + AAC, `-movflags +faststart`로 만든다. `render.mjs`의 `W`, `H`와 `index.html`의 `viewBox`를 이 값으로 맞춘다.
- Chrome에서 JPEG 프레임을 받아 렌더링하면 전체 범위 색상 때문에 `-pix_fmt yuv420p`만 지정해도 `yuvj420p`로 나올 수 있다. 필요하면 ffmpeg의 `scale=in_range=pc:out_range=tv`와 `-color_range tv`로 변환하고 `ffprobe`로 확인한다.
- 길이는 **1분 안팎**으로 만든다. 유튜브가 쇼츠로 인정하는 상한은 2024-10-15부터 3분이므로 1분을 조금 넘겨도 된다(기존 `why-kafka` 64초는 줄이지 않는다).
- 쇼츠 판정은 유튜브가 한다. 영상이 세로(또는 정사각형)이고 길이 상한 안이면 쇼츠로 분류된다. 업로드 스크립트에 따로 지정하는 값은 없다. 제목이나 설명에 `#Shorts`를 붙이면 분류에 도움이 되므로 설명란 끝에 넣는다.
- 쇼츠 화면은 위·아래·오른쪽을 유튜브 UI(제목, 채널명, 좋아요 버튼 등)가 덮는다. **자막과 핵심 그림은 화면 위쪽 약 15%, 아래쪽 약 25%, 오른쪽 가장자리 약 10%를 피해 가운데에 둔다.**
- 자막은 가로 영상보다 한 줄 글자 수를 줄이고 크기를 키운다. 휴대폰 세로 화면에서 읽히는지 확인한다.
- 글 맨 위 영상 칸(`.post-video`)은 16:9라서 세로 영상은 양옆이 비어 보인다. 영상 칸 모양을 바꿀 때는 사용자와 먼저 상의한다.

### 업로드
```
node scripts/youtube-upload.mjs _motion/<슬러그> public _posts/<시리즈>/YYYY-MM-DD-<슬러그>.md
```
- 공개 범위 기본값은 **`public`**이다. 사용자가 무조건 공개로 올리라고 정했으므로 묻지 않고 공개로 올린다. `private`·`unlisted`는 사용자가 따로 요청할 때만 쓴다.
- 영상 업로드가 성공하면 작업 폴더의 `youtube-upload.json`에 ID를 기록한다. 처리 또는 미리보기 반영이 늦어지면 같은 명령으로 기존 ID에서 이어간다. 영상이 정상 재생되고 쇼츠 미리보기에서 썸네일이 확인된 뒤 글에 연결한다. [쇼츠 썸네일 API](https://developers.google.com/youtube/data/reference/rest/v3/thumbnails/set)
- 인증이 필요하다. 첫 실행이면 브라우저가 열리니 사용자가 채널 소유 계정으로 로그인하게 한다. 이후에는 저장된 토큰으로 로그인 없이 올라간다. 로그인 대기 중에는 스크립트가 끝나지 않으므로 백그라운드로 실행한다.
- **`409 Requested entity already exists`**는 같은 영상이 이미 올라갔을 가능성이 있다. 다시 실행하기 전에 사용자에게 유튜브 스튜디오 콘텐츠 탭을 확인해 달라고 한다. 중복 업로드를 막기 위해서다.
- 인증을 받지 않은 API 프로젝트로 올린 영상은 `public`으로 올려도 `private`으로 잠길 수 있다. 업로드 뒤 영상이 실제로 공개 상태인지 사용자에게 확인해 달라고 한다. 잠겼다면 API 검수를 받거나 수동 업로드로 가야 한다.
- 로그인 없이 쇼츠 페이지를 읽어 해당 ID의 재생 상태가 `OK`이고 길이가 0보다 큰지 확인한다. 썸네일은 쇼츠 페이지의 `og:image`와 업로드 응답의 세로 이미지 주소를 대조한다. oEmbed(`/oembed`)는 처리 중인 영상도 200을 주므로 재생 확인에 쓰지 않는다.
- 업로드 성공 직후 `UNPLAYABLE`과 길이 0이 나타날 수 있다. 먼저 잠시 기다렸다가 다시 확인한다. 2026-11-20 쇼츠는 약 30초 뒤 정상 재생됐다. 오래 지속될 때만 실패를 의심한다.
- 2026-11-20 첫 업로드는 `409`로 실패했는데도 영상 항목이 하나 생겼고, 길이 0초로 "처리 중"에 멈췄다. 원인은 확인하지 못했다. 같은 일이 생기면 스튜디오에서 그 항목을 지우고 사용자에게 알린다. 새로 올리기 전에 사용자의 확인을 받는다.
- 이미 올라간 영상의 공개 범위는 이 스크립트(업로드 전용 권한)로 바꿀 수 없다. 스튜디오에서 바꾼다.
- 하루 업로드 한도는 기본 quota 기준 약 6개다(1회 1,600 단위, 하루 10,000 단위).

### 비밀 파일 보호
- `_motion/`의 OAuth 클라이언트 JSON(이름이 `client_`로 시작해 `secret`이 이어지는 파일)과 로그인 토큰 파일은 **Claude가 읽지 않는다.** `.claude/hooks/block-secrets.mjs` 훅이 이 이름이 든 도구 호출을 막고, 스크립트가 직접 파일을 읽는다.
- 그래서 스크립트와 명령, 문서에는 비밀 파일 이름을 그대로 쓰지 못한다. 스크립트는 이름을 조각내 조합한다. 이 구조를 바꾸지 않는다.
- 비밀 파일을 열어 보거나 출력하는 명령을 만들지 않는다. 오류가 나도 파일 내용을 확인하려 하지 않고, 사용자에게 알린다.

### 글에 영상 붙이기
- front matter에 `youtube: <영상 ID>` 한 줄을 넣는다. 전체 주소가 아니라 ID만 넣는다(`https://youtu.be/7SLXOr4UCPE`의 `7SLXOr4UCPE`).
- `_layouts/post.html`이 글 제목 아래, 한 줄 요약 위에 영상을 자동으로 붙인다. 본문에 iframe을 직접 쓰지 않는다.
- 영상이 없는 글은 `youtube:`를 쓰지 않는다.
