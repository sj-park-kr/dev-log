## 3. 글 구성: 동화책 페이지

기준 예시는 [Kafka 1편](../../_posts/kafka/2026-11-15-why-kafka.md), 작성 틀은 [lesson-template.md](../../_drafts/lesson-template.md)다. 다른 글은 아직 예전 형식이라 구조를 따라 하지 않는다.

### 전체 틀
```html
<div class="lesson lesson-hierarchy storybook">
  <svg …아이콘 스프라이트…></svg>          <!-- 05-svg.md -->
  <div class="slide-group">                 <!-- 묶음 3~5개 -->
    <h2 class="slide-group-title">짧은 이름: 설명</h2>
    <section class="slide">…페이지…</section>   <!-- 묶음마다 페이지 2~4장 -->
  </div>
</div>
```
- 글 전체를 `<div class="lesson lesson-hierarchy storybook">`으로 감싼다. `storybook` 클래스가 큰 그림·큰 제목·번호 줄 스타일을 켠다.
- 맨 위 `intro`(질문·도입 문단), "30초 요약", 마지막 "한눈에 다시 보기", 탭은 넣지 않는다. 한 줄 요약은 front matter `summary`가 맡는다.
- 묶음은 3~5개, 묶음마다 페이지는 2~4장, 글 전체는 **8~12페이지**로 맞춘다. 넘치면 다른 편으로 나눈다.
- 묶음 제목은 `짧은 이름: 설명` 꼴로 쓴다(예: `기록: 읽어도 지우지 않아요`). 오른쪽 목차에는 콜론 앞부분만 나오고 번호(1, 1-1)는 CSS가 붙인다.

### 페이지 한 장
```html
<section class="slide">
<h3>카프카는 물류센터예요</h3>               <!-- 이 페이지의 답 한 문장 -->
<svg class="dg" …>…</svg>                    <!-- 큰 그림 한 장 -->
<ol class="steps">                           <!-- 번호 줄 0~3개 -->
<li>가게(프로듀서)는 센터에 맡기기만 해요</li>
<li>센터(브로커)는 소식을 선반(토픽)에 보관해요</li>
<li>담당자(컨슈머)는 필요할 때 와서 가져가요</li>
</ol>
<p class="more">접수증을 언제 주는지는 <a href="…">3편</a>에서 봐요</p>   <!-- 선택 -->
</section>
```
- **한 페이지 = 생각 하나.** 생각이 둘이면 페이지를 나눈다.
- 순서는 언제나 **제목 → 그림 → 번호 줄 → (더 보기)**다. `p.point`, `p.explain`, 표, 문단은 쓰지 않는다.
- 문장 규칙은 [페이지 문장](04-slides-writing.md), 그림 규칙은 [SVG 규칙](05-svg.md)에 있다.

### 읽는 순서 (묶음 짜기)
아래 흐름에서 주제에 맞는 것을 골라 3~5묶음으로 만든다. 각 묶음은 독자가 AI에게 물을 질문 하나에 답한다.

| 순서 | 묶음이 답하는 질문 | 예 (Kafka 1편) |
|---|---|---|
| 1. 문제 | 이게 없으면 뭐가 불편해? | 문제: 직접 알리면 느려요 |
| 2. 정체 | 그래서 이게 뭐야? (비유로) | 물류센터: 카프카가 소식을 맡아 둬요 |
| 3. 원리 | 어떻게 동작해? | 기록: 읽어도 지우지 않아요 |
| 4. 비교 | 비슷한 것과 뭐가 달라? | (3묶음 안의 "메시지 큐는 지우고 카프카는 남겨요") |
| 5. 판단 | 언제 쓰고 뭘 조심해? | 판단: 언제 쓰고 무엇을 조심해요? |

- **주인공을 먼저 소개하지 않는다.** 첫 묶음은 그것이 없을 때 생기는 불편을 그린다.
- 2편부터처럼 개념 하나를 깊게 다루는 글도 같은 흐름이다. "이게 왜 필요해 → 이게 뭐야 → 어떻게 동작해 → 헷갈리는 것과 비교 → 자주 하는 실수·조심할 점" 순서로 짠다.
- 시리즈 첫 편은 전체 지도다. 각 개념은 한 페이지로만 보여 주고 자세한 내용은 해당 편 링크로 넘긴다.
- 비교는 따로 묶음을 만들지 않아도 된다. 비교가 필요한 원리 바로 뒤에 "나란히 비교" 페이지 한 장으로 둔다.
- 마지막 묶음은 "언제 써요 / 안 써요"와 "조심할 점"처럼 독자가 바로 판단에 쓸 페이지로 끝낸다.

### 더 알아보기 (선택)
- 누가, 언제, 왜 만들었는지는 `<details class="origin">`으로 접어 첫 묶음 끝에 하나만 둔다. summary는 `더 알아보기: 누가 왜 만들었을까?`다.
- 안에는 `<p>` 두세 개와 `참고:` 출처 줄만 쓴다. 본문을 이해하는 데 꼭 필요한 내용은 여기에 숨기지 않는다.

### HTML 주의
- `<section>`과 `<details>` 안에는 **빈 줄을 넣지 않는다.** kramdown이 마크다운으로 해석해 HTML이 깨진다.
- 그 안에서는 마크다운 문법(`**`, 표, `-` 목록)을 쓰지 않고 HTML(`<b>`, `<ol>`, `<a>`)을 쓴다.
- 다른 편 링크는 `{{ '/YYYY/MM/DD/<슬러그>/' | relative_url }}`로 쓴다. 슬러그는 파일 이름에서 날짜를 뺀 부분이다.
