## 3. 글 구성
구조 기준은 [승인된 전달 보장 글](../../_posts/kafka/2026-11-15-delivery-semantics.md), 작성 틀은 [lesson-template.md](../../_drafts/lesson-template.md)다. 예시의 형식을 참고하되 새 글의 깊이는 [대상 독자와 목적](01-blog-identity.md)에 맞춘다.

글 전체를 `<div class="lesson lesson-hierarchy">`로 감싸고 한 페이지 한 흐름으로 쓴다. 쉬운 설명과 심화를 탭으로 나누지 않는다. `nav.tabs`, `#easy`/`#dev` 패널, `next-tab` 링크는 넣지 않는다.

**위계**: 주제 묶음은 3~5개로 둔다. 각 묶음은 `<div class="slide-group">`으로 감싸고, `<h2 class="slide-group-title">`로 묶음 제목을 쓴다. 그 안의 슬라이드는 `<section class="slide">`와 h3 제목을 쓴다. CSS가 묶음에는 1, 2, 3, 하위 슬라이드에는 1-1, 1-2처럼 번호를 붙인다. 하위 슬라이드가 하나뿐인 묶음은 만들지 않는다. 제목만 읽어도 무엇에 대한 설명인지 알 수 있게 쓰고, 묶음 제목과 하위 제목을 반복하지 않는다.

**읽는 순서**:
0. **이 글에서 풀 질문** (`<div class="intro">`): 글 맨 위, 첫 묶음 앞에 둔다. `<p class="q">`에 질문 한 줄, 이어서 `<p>` 두 개로 "무엇이 문제인지(앞 편과 이어서)"와 "다 읽으면 무엇을 알게 되는지"를 쓴다.
1. **어떤 문제에서 시작됐나.** 주인공(기술)을 먼저 소개하지 않는다. 그게 없을 때 생기는 문제부터 보여 준다.
2. **더 알아보기: 누가, 왜 만들었을까?** `<details class="origin">`으로 접어 둔다. 언제, 어디서, 누가, 어떤 문제 때문에 만들었는지와 이름의 유래를 쓴다. 문제와 이어지는 곳에 두되, 본문을 읽는 데 꼭 필요한 설명은 여기에 숨기지 않는다.
3. **비유 → 실제 동작**: 같은 개념의 비유 슬라이드 바로 뒤에 "실제로는: …" 슬라이드를 붙인다. 개념마다 이 순서를 반복한다. 정확한 용어는 처음 나올 때 뜻을 한 줄로 풀고 비유와 연결한다. 프로듀서가 / 브로커가 / 컨슈머가 무엇을 하는지 주체를 분명히 쓴다.
4. **정리**: 비유와 실제 용어를 대응시킨 표, 다른 개념과의 관계, 주의사항을 알맞은 주제 옆이나 마지막 묶음에 둔다. 설정·기본값·버전별 변화는 핵심 개념을 이해하는 데 꼭 필요할 때만 넣는다. 다음 편에서 다룰 주제는 개요만 쓴다.
5. **한 줄 정리** (`slide end`): 글 끝에 하나만 둔다. 겹치는 주의사항도 하나로 합친다.
