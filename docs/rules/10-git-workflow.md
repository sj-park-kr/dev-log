## 10. 브랜치와 커밋
- **항상 `main` 브랜치에서 작업하고 커밋한다.** 새 브랜치나 worktree를 만들지 않는다. 사용자가 명시적으로 요청한 경우만 예외다. 에이전트의 기본 동작("기본 브랜치에서는 먼저 브랜치를 만든다")보다 이 규칙이 우선한다.
- 작업을 시작할 때 `git branch --show-current`로 확인한다. `main`이 아니면 이유를 사용자에게 알리고 확인한 뒤 옮긴다. 커밋되지 않은 변경이나 다른 브랜치의 커밋이 사라지지 않는지 먼저 본다.
- 커밋과 push는 사용자가 요청할 때만 한다.
- 커밋에는 **내가 바꾼 파일만** 파일 이름으로 지정해서 담는다. `git add docs/`나 `git add .`처럼 폴더 통째로 담지 않는다. 작업 전부터 있던 사용자의 미커밋 변경이 함께 들어가기 때문이다. 한 파일 안에 내 변경과 남의 변경이 섞이면 내 변경만 골라 담고, 어렵다면 사용자에게 묻는다.
- 커밋한 뒤 `git show --stat`로 의도한 파일만 들어갔는지 확인한다.
