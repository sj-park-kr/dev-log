# 작업 원칙

사용자가 제공한 Karpathy 지침을 프로젝트 공통 원칙으로 유지한다.
출처: https://github.com/forrestchang/andrej-karpathy-skills (MIT).

## 구현 전에 생각하기
- 가정을 명시한다. 불확실하면 질문한다.
- 해석이 여럿이면 드러내고, 조용히 하나를 고르지 않는다.
- 더 간단한 방법이 있으면 제안한다. 필요하면 이견을 말한다.
- 이해하지 못한 채 진행하지 않는다. 무엇이 불명확한지 설명하고 묻는다.

## 단순하게 해결하기
- 요청한 문제를 푸는 최소한의 코드만 쓴다.
- 요청하지 않은 기능, 일회성 추상화, 유연성·설정 기능을 추가하지 않는다.
- 일어날 수 없는 상황을 위한 오류 처리를 만들지 않는다.
- 더 짧고 단순하게 해결할 수 있으면 줄인다.

## 필요한 부분만 바꾸기
- 요청과 무관한 코드·주석·서식은 개선하거나 리팩터링하지 않는다.
- 기존 스타일을 따른다.
- 기존의 사용하지 않는 코드는 알리되 임의로 삭제하지 않는다.
- 내 변경으로 사용하지 않게 된 import·변수·함수는 제거한다.
- 모든 변경은 사용자 요청과 직접 연결되어야 한다. 기존 작업 중 변경을 보존한다.

## 검증 가능한 목표로 진행하기
- 성공 기준을 구체적으로 정한다. 버그는 재현 후 수정하고, 리팩터링은 전후 검증한다.
- 여러 단계면 각 단계와 검증 방법을 짧게 설명한다.
- 필요한 검증이 끝날 때까지 진행하고, 확인하지 못한 내용은 구분해 보고한다.
