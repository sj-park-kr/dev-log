## 8. 게시 전 체크리스트
검증은 빌드와 데스크톱 화면 확인을 기본으로 한다. 모바일 화면·뷰포트 확인은 별도로 요청받았을 때만 한다. 다크 모드에서 본문·코드의 대비와 SVG 글자 잘림을 확인한다. 검증하지 못한 항목은 통과로 표시하지 않고 사유를 보고한다.

- [ ] 주니어·바이브 코딩 독자가 기술의 역할·필요성·관계를 설명할 수 있는가
- [ ] 낯선 용어를 풀어 썼고, 개념 이해에 불필요한 구현·설정 세부사항을 늘어놓지 않았는가
- [ ] 글이 "문제"로 시작하는가, 탄생 이야기는 접혀 있는가
- [ ] 글 맨 위에 "이 글에서 풀 질문"(`intro`)이 있는가
- [ ] 탭 없이 3~5개 묶음으로 이어지고, 비유 바로 뒤에 같은 개념의 실제 동작이 오는가
- [ ] 묶음은 h2, 슬라이드는 h3이며, 하위 슬라이드가 하나뿐인 묶음은 없는가
- [ ] 슬라이드마다 그림이나 표, 핵심 한 문장(`point`), 설명 2~4문장(`explain`)이 있는가
- [ ] 비유가 시리즈의 기존 비유와 같은가
- [ ] `<section>` 안에 빈 줄이 없는가, marker id가 겹치지 않는가
- [ ] 움직임을 빼도 뜻이 통하는가
- [ ] 사실관계를 확인했는가
- [ ] 다시 쓴 point에서 원래 버전·기본값·날짜·동작 조건이 빠지지 않았는가
- [ ] `date`가 현재 시각보다 미래가 아닌가
- [ ] 커밋과 push는 사용자가 확인한 뒤에 한다
