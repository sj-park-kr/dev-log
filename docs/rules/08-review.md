## 8-0. 양식 검토 (초보자 검토 전)
글을 쓰거나 고친 뒤에는 초보자 페르소나 검토보다 먼저 양식 검토를 한다. 양식이 틀린 채로 독자 검토를 돌리면 고칠 페이지를 두고 검토하게 된다. 일부만 고쳤어도 글 전체를 검토한다.

1. **띄우기**: 글마다 Sonnet 서브에이전트(`model: "sonnet"`)를 새로 만든다. [블로그 정체성](01-blog-identity.md), [글 구성](03-article-structure.md), [페이지 문장](04-slides-writing.md), [SVG 규칙](05-svg.md), 아래 [게시 전 체크리스트](#8-1-게시-전-체크리스트)를 읽고 글 파일과 대조하게 한다. 기준 예시 [Kafka 1편](../../_posts/kafka/2026-11-15-why-kafka.md)도 함께 읽게 한다.
2. **파일 수정 금지**: 읽고 보고만 한다. 어긴 곳을 묶음·페이지 제목과 어긴 규칙과 함께 적게 한다.
3. **반영**: 작성자가 모두 고친 뒤 초보자 페르소나 검토로 넘어간다. 규칙이 애매해 판단이 갈리면 사용자에게 묻는다.

## 8. 초보자 페르소나 검토
양식 검토를 마친 글을 매번 초보자 페르소나 서브에이전트(Agent 도구)로 검토한다. 작성자는 내용을 이미 알아서 막히는 곳을 스스로 찾기 어렵다.

1. **띄우기**: 글마다 Sonnet 서브에이전트(`model: "sonnet"`, [작업별 모델](11-agent-models.md))를 새로 만든다. 프롬프트에는 글 파일 경로, 같은 시리즈의 앞 편 경로(있으면), 페르소나, 보고 형식만 준다. 작성자의 의도나 정답 설명은 넣지 않는다.
2. **페르소나**: 프로그래밍을 막 배우기 시작했고 서버·네트워크 같은 용어가 낯설다. 긴 글을 읽다 지치면 그만 읽는다. 이 글과 같은 시리즈의 앞 편만 읽었다. 모르는 것을 아는 척 넘기지 않는다.
3. **파일 수정 금지**: 서브에이전트는 읽고 보고만 한다. 수정은 작성자(메인 에이전트)가 한다.
4. **보고 형식**: 아래 다섯 가지를 해당 페이지 제목과 함께 적게 한다.
   - 그림만 보고 뜻을 몰랐던 페이지: 무엇이 헷갈렸는지
   - 이해하지 못한 문장: 원문 인용, 막힌 이유
   - 괄호 풀이 없이 처음 나온 용어
   - 글자가 많아 읽기 싫었던 페이지
   - 읽다가 떠오른 질문 (AI에게 따로 물어보고 싶어진 것)
5. **반영**: 보고를 하나씩 따져 셋 중 하나로 처리한다.
   - 처음 읽는 데 꼭 필요한 설명이 빠졌다면 그림을 고치거나 번호 줄을 고친다. 한 페이지에 안 들어가면 페이지를 새로 만든다. 글자를 늘려서 해결하지 않는다.
   - 흐름 밖의 궁금증이면 다른 편에서 다루는지 확인해 `p.more` 링크로 잇는다. 다룰 편이 없고 꼭 남길 질문이면 [작성자 질문](09-author-questions.md)의 `초보 독자 Q.` 접이식으로 둔다.
   - 억지스럽거나 시리즈 범위 밖이면 반영하지 않는다.
6. **다시 검토**: 그림이나 페이지 구성을 크게 바꿨다면 같은 방식으로 한 번 더 돌린다. 그 이상 반복하지 않는다.
7. **보고**: 사용자에게 고친 곳, 링크·질문으로 남긴 곳, 반영하지 않은 곳과 이유를 짧게 알린다.

## 8-1. 게시 전 체크리스트
검증은 빌드와 데스크톱 화면 확인이 기본이다. 모바일 화면은 따로 요청받았을 때만 본다. 다크 모드에서 글자 대비와 SVG 글자 잘림을 확인한다. 확인하지 못한 항목은 통과로 표시하지 않고 사유를 보고한다.

**정체성**
- [ ] 그림만 넘겨 봐도 흐름을 따라갈 수 있는가
- [ ] 이야기처럼 이어지는 서술, 문단, 표가 없는가
- [ ] 사람들이 AI에게 물을 질문(뭐야·왜·어떻게·뭐가 달라·언제·뭘 조심)의 답이 페이지 제목으로 보이는가
- [ ] 설치·명령어 나열이 없는가

**구성**
- [ ] 글 전체가 `lesson lesson-hierarchy storybook`으로 감싸져 있는가
- [ ] `intro`, 30초 요약, 한눈에 다시 보기, 위젯이 없는가
- [ ] 묶음 3~5개, 묶음마다 페이지 2~4장, 전체 8~12페이지인가
- [ ] 묶음 제목이 `짧은 이름: 설명` 꼴인가
- [ ] 첫 묶음이 문제로 시작하고 마지막 묶음이 판단(언제 쓰나·조심할 점)으로 끝나는가
- [ ] 더 알아보기(origin)는 첫 묶음 끝에 접혀 있는가 (있을 때)

**페이지**
- [ ] 모든 페이지가 제목 → 그림 → 번호 줄(0~3개) → 더 보기(선택) 순서인가
- [ ] 제목이 답 한 문장이고 25자 안팎인가
- [ ] 번호 줄이 3개 이하이고 한 줄이 한 문장(25자 안팎)인가
- [ ] 번호 줄이 그림 속 글자를 되풀이하지 않는가
- [ ] 기술 용어가 처음 나올 때 비유 이름 옆 괄호로 붙었는가
- [ ] 설명용 숫자에 `(예시)` 표시가 있는가

**그림**
- [ ] 그림마다 생각 하나만 보여 주고 글자는 이름표 위주인가
- [ ] 비교는 한 그림 안에 같은 기준으로 나란히 그렸는가
- [ ] 사물이 아이콘이고 `<use>`로 쓴 `i-…`가 모두 스프라이트에 정의돼 있는가
- [ ] marker id가 겹치지 않는가, 글자가 잘리거나 겹치지 않는가
- [ ] 비유가 시리즈의 기존 비유와 같은가

**사실과 파일**
- [ ] 사실관계를 [사실 확인](07-fact-checking.md) 기준으로 확인하고 출처를 `p.more`나 origin에 남겼는가
- [ ] 다른 편 링크가 실제로 열리는가
- [ ] 기존 글을 옮겼다면 원래 버전·기본값·날짜·동작 조건이 빠지지 않았는가
- [ ] `<section>`·`<details>` 안에 빈 줄이 없는가
- [ ] `date`가 현재 시각보다 미래가 아닌가
- [ ] 양식 검토와 초보자 페르소나 검토를 했는가
- [ ] 커밋과 push는 사용자가 확인한 뒤에 하는가
